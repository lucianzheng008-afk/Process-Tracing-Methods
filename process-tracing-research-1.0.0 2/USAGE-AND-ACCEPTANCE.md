# 使用、配置与十项验收

## 快速调用

最小调用可以只有一个问题：

> 使用 process-tracing-research，解释 1990–1998 年案例 A 中，国际规范如何通过国内精英互动促成政策 Y。请构建并比较至少一个竞争机制，先给研究设计和证据计划，再搜索可核验材料，最后交付中文论文式分析、机制图、时间线和证据更新表；证据不足时收缩结论。

如果已有材料，可追加：理论文献、案例 PDF/档案、访谈、已有大纲、字数、引用体例、允许检索的平台、必须保留的命题和截止时间。Skill 会先登记合同，不会把遗漏参数自动填成事实。

## 1. 该 Skill 接收什么类型的输入？

可接收：

- 经验现象、理论争论或初步研究问题；
- 一个或多个国家、危机、组织、政策、战争、民主化或制度变迁案例；
- 教材、方法文献、领域理论、论文 PDF、档案、访谈、新闻、数据与时间线；
- 用户已有的变量、机制、大纲、案例选择和结论草稿；
- 输出语言、文类、字数、引用体例、检索权限、图表要求和不确定性偏好。

最低可用输入是“待解释结果 + 案例/时期”。若只有宽泛主题，Skill 先产出可选择的 bounded research question，并在不虚构材料的前提下继续完成研究设计和检索计划。

## 2. 它将按照什么顺序开展研究？

固定因果顺序是：

1. 任务合同；
2. 适用性与问题诊断；
3. 方法、理论、案例三类文献地图；
4. 核心解释与竞争解释；
5. 实体—活动—传导机制；
6. 案例、人口与时间设计；
7. 先验经验指纹和否证标准；
8. 来源检索、谱系与可信度审计；
9. 时间线和关键节点重建；
10. 逐项证据评价、定性/显式贝叶斯更新；
11. 自下而上聚合、反事实与范围分析；
12. 整合写作、图表和质量审查。

理论建构型研究允许在步骤 5–10 之间迭代，但发现材料与独立验证材料必须分开记录。

## 3. 每个阶段产生什么中间成果？

| 阶段 | 可审计成果 |
|---|---|
| 合同/诊断 | `project-metadata.json`、问题句、结果与结论上限 |
| 文献准备 | 方法/理论/案例来源表、访问状态、允许支持的主张 |
| 理论设计 | `competing-explanations.csv`、范围条件、先验 |
| 机制建构 | `mechanism-evidence-matrix.csv`、机制图草案 |
| 案例设计 | `case-comparison.csv`、人口边界、异质性风险 |
| 证据规划 | 经验指纹、替代生成过程、否证标准、目标来源 |
| 来源收集 | `source-register.csv`、`source-dependence-matrix.csv`、source-family 谱系、搜索/访问日志 |
| 过程重建 | `timeline.csv`、关键节点和滞后窗口 |
| 证据检验 | `evidence-register.csv`、`bayesian-update.csv` |
| 综合推断 | `claim-register.csv`、论证路线图、结论上限 |
| 迭代留痕 | `revision-register.csv`、被替换状态、理由与新证据 |
| 写作/图表 | 论文正文、`visual-register.csv`、机制/时间/比较图表 |
| 质量控制 | 自动审计 JSON/文本报告和人工 Gate A–H 清单 |

所有成果共享 ID，因此可追踪“一句结论来自哪项证据、哪个来源、哪个机制环节”。

## 4. 它如何判断因果机制是否得到支持？

它不以“材料多”或“存在先后关系”为标准，而按四层聚合：

1. 理论层：活动发生时指纹出现的可能性，以及无该活动时替代过程产生同一指纹的可能性；
2. 经验层：实际观察的含义、来源可信度、独立性和访问概率；
3. 比较层：观察在核心与最佳竞争解释下的相对预期程度；
4. 链条层：观察 → 命题 → 机制环节 → 完整机制逐级聚合。

每个必要环节都获得有诊断力的支持、关键来源可审计、依赖被折扣且竞争解释被公平比较时，才能说“该 bounded mechanism 在本案例中得到支持”。整条链的强度不得超过最弱必要环节。

## 5. 它如何处理证据冲突和竞争性解释？

冲突材料不按票数决定。Skill 登记各来源的接近程度、能力、动机、保存/披露过程和共同信息源，区分事实冲突、语义冲突与解释冲突，并寻找生成过程不同的新材料。

至少一个真正的竞争解释必须拥有自己的实体、活动、时序、指纹和不友好证据。每项关键证据都比较在核心/竞争解释下的预期程度。解释可以互补；若证据不具判别力，状态标为“未裁决”，不会被语言包装成“排除”。

## 6. 它最终会输出哪些文字与图表？

按任务规模自主组合：标题、摘要、问题意识、文献争论、理论框架、核心概念、范围条件、完整机制、竞争解释、研究设计、案例选择、来源评价、案例背景、分阶段过程分析、关键节点、证据聚合、研究发现、贡献、结论边界、参考文献和附录编码表。

图表可包括：

- 理论因果机制图；
- 过程追踪时间线；
- 机制—证据矩阵；
- 竞争解释比较表/树；
- 定性或显式贝叶斯更新表；
- 多案例比较表；
- 范围条件与向外滚雪球图；
- 论证路线图或证据热图。

图表由与正文相同的 ID 生成，标题和图注必须说明推断边界。

## 7. 它与一般“论文写作 Skill”相比，独特能力是什么？

一般写作 Skill 优化结构、段落、引文和表达；本 Skill 额外执行案例内因果识别：

- 选择过程追踪变体和机制分辨率；
- 把因果标签拆成实体、活动与 productive continuity；
- 先验设计经验指纹与否证标准；
- 区分理论诊断性、经验可信度、访问和来源依赖；
- 对核心与竞争机制做相对似然更新；
- 从证据到命题、环节和机制逐层聚合；
- 控制单案例的推论上限与外部效度；
- 自动检查正文、表格、时间线和图表的 ID 一致性。

它可以调用通用写作能力，但不能被通用润色替代。

## 8. 它如何避免历史叙述、理论堆砌或证据罗列？

- 防历史叙述：每个事件必须关联机制环节、命题、证据与分析角色；不改变推断的背景被压缩。
- 防理论堆砌：每个理论必须产生实体—活动链、范围条件、可观测含义和不友好证据；只有标签而无预测的理论不进入正文核心。
- 防证据罗列：每项材料必须回答“支持哪个命题、相对哪个替代、可靠性和依赖如何、改变了多少置信度”。
- 段落采用“理论功能—案例条件—行动—证据—传导—竞争解释—更新/边界”的固定分析单元。

范文中的 Tannenwald 重构和失败修复示例分别展示合格写法与典型越界。

## 9. 它如何检查自己是否完成了真正意义上的过程追踪？

双重审查：

1. `validate_skill.py` 检查 Skill 的结构、frontmatter、链接、模板 schema 和占位符；
2. `audit_project.py` 检查研究项目中的缺失机制字段、未知 ID、重复来源家族、低访问下的错误否证、无竞争解释、无证据结论、时间错误和更新缺失。

随后人工执行 `references/quality-gates.md` 的 Gate A–H：问题/设计、机制、案例/时间、来源、证据/更新、竞争解释、写作/图表、贡献/推广。任何阻断项未通过，必须修订或降低结论等级。自动 PASS 只说明结构可审计，不代表事实或因果判断已经被机器证明。

## 10. 用户应如何调用、配置和迭代使用？

### 调用

明确说“使用 process-tracing-research”，并给主题、案例/时期和目标输出；也可以直接提出“如何在案例内通过机制解释结果”，其触发描述会匹配。

### 配置

复制 `templates/` 到项目目录，在 `project-metadata.json` 设置设计变体、机制分辨率、语言、案例、主解释、时间边界、检索范围和不确定性策略。保留 CSV 表头与 ID 规则。

### 迭代

推荐四轮：

1. 只审问题、机制和竞争解释；
2. 审案例选择、证据计划和检索缺口；
3. 导入新材料，重跑来源审计与更新；
4. 生成正文/图表并做最终 Gate A–H 审查。

用户可要求“冻结已确认事实，只重做 P-3”“加入一个国内政治竞争机制”“把结论限定到 1990–1994”“用新解密档案更新 U-4”。稳定 ID 使局部迭代不会破坏其他部分。

## 验收结论

本 Skill 可在材料充分时执行完整研究，也可在材料不足时完成高质量设计、搜索和推论边界。它不会因为缺一份档案而过早停止，但也不会用流畅叙事替代缺失证据。可运行性由模板、脚本、真实案例范文、失败范例和端到端合成 fixture 共同验证。
